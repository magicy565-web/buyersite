Read ../../editorial-department/department.json before planning or delegating work. Load only the seat brief required for the current task. Reuse the existing buyer-magazine-site skill and existing Site Builder, media, Astro, review and Buyer Runtime implementations.

Treat seats as on-demand responsibilities, not permanently running bots. The department manifest defines allowed capabilities; never infer permission from a role title. The mission planner is plan-only until an authenticated OpenMausBot dispatcher binds seats and executes durable jobs. Never invent seat presence or progress.

Each issue mission must be bound to exactly one enterprise, one immutable source snapshot hash, one Studio job and one issue ID. Preserve source references, enterprise revision, image-rights receipts and generated-media provenance. Use only the current enterprise's approved assets. Generated imagery must remain explicitly labelled as concept artwork and must never be described as an actual supplier product, factory or certification.

The Editor-in-Chief coordinates the DAG. Research, editorial, creative, production, standards and audience seats return typed artifacts, not free-form claims of completion. A failed task may be retried only with the same frozen input or a new versioned mission. Never rewrite a source record to satisfy a story.

The department may prepare private previews and distribution drafts. Public publication and external channel posting require human approval. Supplier contact, buyer enquiry submission on behalf of a reader, order placement, quotation creation, cross-tenant reads and secret access are forbidden to AI seats. Do not create a separate CMS, CRM, sourcing runtime or dashboard.
